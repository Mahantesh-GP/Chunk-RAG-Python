# PMO Dashboard — Playwright Regression Testing

## Overview

This document explains the regression testing approach for PMO dashboards that are generated by Python scripts and served as static HTML files on an internal server.

**The core problem this solves:** Every time a bug fix or vulnerability fix is applied to the Python generator script, we need confidence that the generated HTML dashboard still renders correctly — tables, charts, KPIs, and filters all intact — before deploying to the internal server.

---

## Folder Structure

```
your-project/
├── package/
│   └── dashboard/
│       └── audit/
│           └── a.html              ← generated by Python script
├── tests/
│   ├── screenshots/                ← auto-created, stores PNG outputs
│   └── test_dashboard.py           ← Playwright test file
├── docs/
│   └── playwright-testing.md       ← this file
└── requirements.txt
```

> Each dashboard lives at: `package/dashboard/<dashboard_name>/<file>.html`  
> The test file reads from this path automatically.

---

## Why Playwright?

Playwright opens the generated HTML in a **real Chromium browser** — the same engine used in production. This means:

- It catches broken layouts that simple file checks would miss
- It detects JavaScript errors at runtime
- It renders charts and tables exactly as a user would see them
- It produces screenshots you can visually verify

It is **not** used for generating dashboards or scheduling — that is handled by your Python scripts separately.

---

## Test Categories

### 1. Structure Tests ✅ (active)

Verifies that all key dashboard elements are present after HTML generation.

| Check | What it verifies |
|---|---|
| Page title | HTML `<title>` is not empty |
| Tables | At least one `<table>` exists |
| KPI cards | Elements matching `.kpi-card` or `[class*='kpi']` exist |
| Charts | At least one `<canvas>` or `<svg>` exists |
| Filters | At least one `<select>` or filter element exists |

If any of these fail after a fix, it means the Python generator script broke something structural.

---

### 2. Security Tests 🔒 (commented — enable when ready)

These tests verify the vulnerability fixes that were applied: **CSP headers, XSS prevention, and JS safety**.

| Test | What it checks |
|---|---|
| `test_csp_meta_tag` | CSP `<meta>` tag exists, has `script-src`, no `unsafe-inline` |
| `test_no_inline_event_handlers` | No `onclick`, `onerror`, `onload` etc. on arbitrary elements |
| `test_no_javascript_protocol` | No `href="javascript:..."` links |
| `test_no_eval_in_scripts` | No `eval()` calls inside inline `<script>` blocks |
| `test_console_no_errors` | No JavaScript errors in browser console after load |

**To enable:** Open `test_dashboard.py` and uncomment the security test functions, then add them back to the `active_tests` list inside `run_all()`.

---

### 3. Visual / Screenshot Test 📸 (active)

Takes a full-page screenshot of the rendered dashboard and saves it to `tests/screenshots/<dashboard_name>.png`.

Use this to:
- Visually confirm nothing looks broken after a fix
- Compare before/after screenshots when reviewing a PR
- Share a quick preview with the PMO team without opening the HTML

---

## Developer Workflow

This is the recommended flow every time you fix a bug or vulnerability:

```
Fix code in Python generator
        ↓
Run:  python package/dashboard/audit/generate.py
        ↓
Run:  python tests/test_dashboard.py
        ↓
Check terminal output — all ✅?
        ↓
Open tests/screenshots/audit.png — looks correct?
        ↓
Commit and copy HTML to internal server
```

If any test fails, fix the issue and re-run from the top.

## Setup Instructions

### Step 1 — Install dependencies

```bash
pip install -r requirements.txt
playwright install chromium
```

### Step 2 — Configure the dashboard path

Open `tests/test_dashboard.py` and update these two lines at the top:

```python
DASHBOARD_NAME = "audit"       # ← folder name under package/dashboard/
DASHBOARD_FILE = "a.html"      # ← your generated HTML filename
```

For a different dashboard, just change these values.

### Step 3 — Generate the HTML first

```bash
python package/dashboard/audit/generate.py
```

The HTML must exist before running tests.

### Step 4 — Run the tests

```bash
# Option A: direct Python runner
python tests/test_dashboard.py

# Option B: via pytest (more detailed output)
pytest tests/test_dashboard.py -v
```

---

## Adding a New Dashboard

When a new dashboard is added to the project:

1. Place its generator script at `package/dashboard/<name>/generate.py`
2. Copy `tests/test_dashboard.py` and rename it, e.g. `test_resource_dashboard.py`
3. Update `DASHBOARD_NAME` and `DASHBOARD_FILE` in the new test file
4. Run it the same way

No changes needed to the folder structure or requirements.

---

## Enabling Security Tests

Once the vulnerability fixes are confirmed stable, enable security tests by:

1. Opening `tests/test_dashboard.py`
2. Removing the `#` comment prefix from the security test functions
3. Adding them to `active_tests` inside `run_all()`:

```python
active_tests = [
    test_structure,
    test_screenshot,
    test_csp_meta_tag,                  # ← uncomment
    test_no_inline_event_handlers,      # ← uncomment
    test_no_javascript_protocol,        # ← uncomment
    test_no_eval_in_scripts,            # ← uncomment
    test_console_no_errors,             # ← uncomment
]
```

## Scheduling (Daily Refresh)

Since dashboards refresh daily, you can hook the test into your existing schedule:

### Windows Task Scheduler

```bat
@echo off
python package\dashboard\audit\generate.py
python tests\test_dashboard.py
```

### Cron (Linux)

```bash
0 6 * * * cd /path/to/project && python package/dashboard/audit/generate.py && python tests/test_dashboard.py
```

### Azure DevOps Pipeline

```yaml
schedules:
  - cron: "0 6 * * *"
    displayName: Daily Dashboard Refresh
    branches:
      include: [main]

steps:
  - script: pip install -r requirements.txt && playwright install chromium
    displayName: Install dependencies

  - script: python package/dashboard/audit/generate.py
    displayName: Generate dashboard HTML

  - script: python tests/test_dashboard.py
    displayName: Run regression tests

  - task: PublishPipelineArtifact@1
    inputs:
      artifactName: screenshots
      targetPath: tests/screenshots
```
